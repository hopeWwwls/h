# ربات آرشیو کانال (تلگرام → بله)

ربات ادمین‌محوری که با یک حساب userbot تلگرام به کانال‌های موردنظر گوش می‌دهد،
پیام‌ها و رسانه‌هایشان را جمع می‌کند، در یک فایل HTML+ZIP رمزگذاری‌شده بسته‌بندی
می‌کند و از طریق بات بله (Bale) تحویل ادمین می‌دهد. برای زمانی طراحی شده که
دسترسی مستقیم به تلگرام قطع باشد ولی بله در دسترس بماند.

## تغییرات این نسخه

1. **حذف uploadkon.ir** — فقط `imgurl.ir` (فایل `uploader.py`) باقی مانده است.
2. **حذف کامل SMS** — فایل `sms_sender.py` و هرگونه وابستگی به `sms.ir` حذف شد.
3. **مقاومت در برابر کرش** — کل حلقهٔ اصلی در `run_forever()` اجرا می‌شود: اگر
   `main()` به هر دلیلی (قطعی شبکه، خطای غیرمنتظره و…) متوقف شود، بعد از یک
   تأخیر کوتاه (که با هر بار شکست بیشتر می‌شود) خودکار از نو راه‌اندازی می‌شود.
   همچنین یک `error_handler` سراسری اضافه شده که خطای داخل هندلرها را فقط لاگ
   و به ادمین گزارش می‌کند، بدون این‌که کل پردازش را متوقف کند.
4. **ذخیره و بازیابی وضعیت کار ناتمام** — پیش از شروع هر export، مشخصات آن
   (کانال‌ها، تعداد پیام، سقف حجم، روش تحویل) در `state.json` ذخیره می‌شود. اگر
   ربات وسط کار قطع شود، در راه‌اندازی بعدی به‌صورت خودکار همان درخواست دوباره
   به صف اضافه می‌شود (به ادمین هم اطلاع داده می‌شود). با پایان موفق/ناموفق یا
   لغو دستی یک درخواست، رکورد آن پاک می‌شود.
5. **پاک‌سازی خودکار فایل‌های موقت** — هم در استارت‌آپ و هم هر
   `TEMP_CLEANUP_INTERVAL_SECONDS` ثانیه (پیش‌فرض ۱۵ دقیقه) پوشه‌های نصفه‌کارهٔ
   export/آواتار پاک می‌شوند. فایل زیپ/آپلود هر job هم در بلاک `finally` همان
   job (نه فقط در پایان موفق) پاک می‌شود؛ یعنی به‌محض ارسال یا آپلود، چیزی از آن
   روی هاست باقی نمی‌ماند.
6. **دستور `/status` واضح‌تر** — به‌صراحت می‌گوید ربات «روشن و بیکار»، «در صف»
   یا «مشغول انجام کدام export» است.
7. **انتخاب روش تحویل خروجی** — بعد از انتخاب کانال‌ها و تعداد پیام، ربات با دو
   دکمه می‌پرسد:
   - 📤 آپلود در `imgurl.ir` (رفتار قبلی: یک لینک رمزشده ارسال می‌شود)
   - 📎 ارسال مستقیم فایل به‌صورت `jpg` در بله — اگر حجم بیش از ۵۰ مگابایت
     (سقف واقعی بله) باشد، به چند پارت zip تقسیم می‌شود که هرکدام با پسوند
     `.jpg` نام‌گذاری و ارسال می‌شوند (`export_part1of3.jpg` و…).
   دستور متنی `/export all direct` هم همین انتخاب مستقیم را بدون رفتن به منوی
   دکمه‌ای انجام می‌دهد؛ بدون کلمهٔ `direct`، پیش‌فرض همان آپلود در imgurl.ir است.
8. **راهنمای شفاف‌تر** — متن `/start` و `/help` به‌صورت مرحله‌به‌مرحله توضیح
   می‌دهد که چه دستوری چه کاری می‌کند.

## متغیرهای محیطی

| متغیر | توضیح |
|---|---|
| `BOT_TOKEN` | توکن بات بله |
| `ADMIN_ID` | آیدی عددی ادمین (تنها کاربر پیش‌فرض مجاز) |
| `API_ID`, `API_HASH` | مشخصات اپ تلگرام برای userbot |
| `SESSION_STRING` | خروجی `session_setup.py` |
| `ZIP_PASS` | رمز فایل ZIP خروجی |
| `CRYPT_PASS` | رمز لایهٔ رمزگذاریِ لینک نهایی |
| `IMGURL_SESSION` | (اختیاری) کوکی نشست imgurl.ir برای آپلود پایدارتر |
| `DATA_DIR` | (اختیاری) مسیر دادهٔ پایدار؛ روی Railway یک Volume به این مسیر وصل کنید |
| `STATE_BACKUP_DIR`, `STATE_BACKUP_KEEP`, `STATE_BACKUP_INTERVAL_SECONDS` | تنظیمات بکاپ‌گیری از state |
| `TEMP_CLEANUP_INTERVAL_SECONDS` | فاصلهٔ پاک‌سازی دورهٔ فایل‌های موقت (پیش‌فرض ۹۰۰ ثانیه) |
| `MEDIA_CONCURRENCY`, `MAX_MEDIA_BYTES` | کنترل دانلود هم‌زمان رسانه و سقف حجم هر فایل رسانه |

**نکتهٔ مهم دربارهٔ `DATA_DIR`:** برای این‌که با هر ری‌استارت روی Railway
فهرست کانال‌ها، کاربران مجاز، و export ناتمام از دست نروند، `DATA_DIR` باید
روی یک Volume پایدار (نه دیسک موقتیِ کانتینر) قرار بگیرد.

## دستورها

راهنمای کامل و به‌روز همیشه با دستور `/help` در خود ربات قابل مشاهده است.

## نصب

```bash
pip install -r requirements.txt
python session_setup.py   # یک‌بار، برای ساخت SESSION_STRING
python main.py
```

روی Railway، `Procfile` این پروژه از نوع `worker` است و مستقیماً `python -u main.py`
را اجرا می‌کند.
